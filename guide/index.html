03新しい版(バージョン2)を出す

Google ログインの修正は手元のファイルに入っているだけで、Play にはまだ届いていません。所要時間は5分ほどです。

  1. 内部テストの画面を開く
    Play Console →「ADHD時間管理」→ 左メニュー「テストとリリース」→「テスト」→「内部テスト」
  2. 「新しいリリースを作成」を押す
    右上の青いボタンです。
  3. AAB をドラッグ&ドロップ
    ビルドした app-release.aab を入れます。表の中に新しいバージョン(例:「2 (1.0.1)」)が出れば成功です。
  4. リリースノートを書く
    欄の中身を全部消して、次を貼り付けます。
    <ja-JP> Googleログインの不具合を修正 </ja-JP>
  5. 「次へ」→「保存して公開」
    黄色の警告は無視して大丈夫です。赤いエラーが出たら 09 を見てください。「内部テスターに公開」と表示されたら完了です。

04スマホを Play 版に入れ替える

今スマホに入っているのは、確認のためにパソコンから直接入れた版です。署名が Play 版と違うので、このままだと Play からの更新が失敗します。

  1. 必要ならバックアップを取る
    アプリの「設定」→「バックアップ」→「エクスポート」。予定を入れていなければ不要です。
  2. 「ADHD時間管理」をアンインストール
    同じアイコンが複数ある場合は、テスト中に入れた古い版もまとめて消して大丈夫です(古い版の中の予定も消えます)。
  3. Play ストアから入れ直す
    内部テストの参加リンク(02)をスマホで開く →「Google Play でダウンロード」。バージョン2の公開直後は、反映まで数分〜1時間ほどかかることがあります。
  4. 権限を許可して Google ログインを試す
    初回に通知・アラームの許可を求められます。「設定」→「Googleカレンダー連携」→「Googleアカウントでログイン」。「Google で確認されていません」と出たら「続行」で進みます(テスト中の正常な表示です)。
  5. 必要ならバックアップを戻す
    「設定」→「バックアップ」→「インポート」。

05クローズドテスト(12人以上・14日間)

2023年11月以降に作った個人のデベロッパー アカウントは、製品版の前に「12人以上のテスターが、14日間続けて参加した」クローズドテストが必要です。一番時間がかかる工程なので、早めに始めてください。

準備:テスター用の Google グループを作る

  1. Google グループを作る
    groups.google.com →「グループを作成」。名前の例:adhd-jikan-testers。「グループに参加できるユーザー」は「ウェブ上の誰でも参加をリクエストできる」か「招待されたユーザーのみ」。メンバーの一覧は「グループのメンバー」に限定して、テスター同士のメールアドレスが見えないようにします。
  2. テスターを集める(12人以上。余裕をみて15人ほど)
    家族・友人・SNS で募集します。途中で抜ける人が出ると14日が数え直しになることがあるので、多めに集めてください。テスターの Google アカウントのアドレスを聞いて、グループに追加します。

Play Console でクローズドテストを作る

  1. トラックを開く
    「テストとリリース」→「テスト」→「クローズド テスト」→ 最初からある「Alpha」トラックの「管理」(無ければ「トラックを作成」)。
  2. 国と地域を選ぶ
    「国 / 地域」タブ →「国 / 地域を追加」→「日本」にチェック → 保存。
  3. テスターを登録する
    「テスター」タブ →「Google グループ」を選び、グループのアドレス(例:adhd-jikan-testers@googlegroups.com)を入れて保存。「フィードバック用 URL またはメールアドレス」には公開用のメールアドレス。
  4. リリースを作る
    「リリース」タブ →「新しいリリースを作成」→「ライブラリから追加」で、内部テストに出したのと同じ AAB(2 (1.0.1))を選ぶ → リリースノート →「次へ」→「保存して公開」。
  5. Google の審査を待つ
    クローズドテストは初回に審査があります(数時間〜数日)。「公開の概要」で状態を確認できます。通ると「テスター」タブに参加用リンクが出ます。
  6. テスターに案内を送る
    下の文をコピーして、参加用リンクを入れて送ります。
    ADHD時間管理(アラーム・タイマー・予定管理のアプリ)のテストに協力してもらえませんか? 1. このリンクを開いて「テスターになる」を押す: (ここに参加用リンク) 2. 同じページの「Google Play でダウンロード」からインストール 3. 14日間はアンインストールしないでください(ときどき開いてもらえると助かります) 気づいたことがあれば、Play ストアのアプリページの「フィードバック」か、〈公開用のメールアドレス〉まで。
  7. 14日間待つ
    ダッシュボードに「クローズド テストの進捗」が出ます。人数と日数の条件を満たすと、製品版の申請ができるようになります。
テスターにも Google ログインを試してもらう場合:Google Cloud の「Google Auth Platform」→「対象」→「テストユーザー」に、その人のアドレスを追加してください(最大100人)。追加しないと、その人はログインできません。iCal 方式(方法1)なら登録なしで使えます。

06製品版を申請して公開する

  1. 製品版へのアクセスを申請する
    ダッシュボードの「製品版へのアクセスを申請」。テストの内容、テスターからのフィードバック、それを受けて直したことなどのアンケートに答えます。正直に、具体的に書いてください(例:「横画面でボタンが押せない不具合を直した」)。審査は数日〜1週間ほどです。
  2. 製品版のリリースを作る
    承認されたら「テストとリリース」→「製品版」→「国 / 地域」で日本を追加 →「新しいリリースを作成」→ ライブラリから AAB を追加 → リリースノート →「次へ」。
  3. 審査に送信する
    「公開の概要」で「審査に送信」。数時間〜数日で審査が終わり、通れば Google Play で誰でもダウンロードできるようになります。
  4. サイトの表示を「公開中」に変える
    サイトのトップにある「Google Play で公開準備中」を、ストアへのリンクに変えます。ストアの URL は https://play.google.com/store/apps/details?id=〈パッケージ名〉 です。

07Google ログインを誰でも使えるようにする(任意)

今は「テスト中」なので、テストユーザーに登録した人しか Google ログインを使えません。一般の人にも使ってもらうには、Google の確認(審査)が必要です。カレンダーの読み書きは「機密性の高い権限」のため、審査に数週間かかることがあります。

  1. ブランディングを埋める
    「Google Auth Platform」→「ブランディング」で、アプリのホームページ(サイトの URL)、プライバシーポリシー、アプリのロゴ(icon_512.png を 120×120 に縮小したもの)を設定します。「ユーザー サポートメール」はログイン画面に表示されます。公開用のアドレスにしたい場合は、先に「IAM と管理」でそのアドレスをプロジェクトのオーナーとして追加します。
  2. 承認済みドメインを確認する
    ホームページのドメイン(〈GitHubユーザー名〉.github.io)の所有を Google Search Console で確認します(「URL プレフィックス」でサイトの URL を入れ、HTML ファイルを GitHub のリポジトリに置く方法)。
  3. 「アプリを公開」→ 確認を申請
    「対象」→「アプリを公開」。「検証センター」の案内に沿って、カレンダーの権限を使う理由と、実際に使っている様子の動画(YouTube の限定公開)を提出します。
急がなくて大丈夫です:審査が終わるまでも、アプリの公開はできます。一般の人は iCal 方式(方法1)でカレンダーを取り込めるので、そちらを案内してください。

08今後のアップデートの出し方

アプリを直して新しい版を出すときの手順です。AI のコーディング アシスタントを使っている場合は、1〜3を任せることもできます。

  1. バージョンを上げる
    pubspec.yaml の version: の数字を両方上げます。+ の後ろの数字は、毎回かならず前より大きくします(同じだとアップロードできません)。例:1.0.1+2 → 1.0.2+3
  2. AAB を作る
    Flutter プロジェクトのフォルダでターミナルを開いて実行します(フォルダのパスに日本語が含まれるとビルドに失敗することがあります)。
    flutter build appbundle --release --dart-define=STORE_BUILD=true
    できたファイル:build\app\outputs\bundle\release\app-release.aab
  3. 動作を確かめる
    flutter analyze flutter test
    エラー0・テストがすべて合格なら OK です。
  4. Play にアップロード
    03 と同じ手順で、出したいトラック(内部テスト・クローズドテスト・製品版)に新しいリリースを作ります。

09困ったとき

これまでに実際に出たエラーと、その直し方です。

「パッケージ名は adhd.time.management とする必要があります」
アップロードした AAB が古い名前で作られています。android/app/build.gradle.kts の applicationId が adhd.time.management になっているか確認して、作り直してください。
「バージョン コード ○ はすでに使用されています」
pubspec.yaml の + の後ろの数字を、今までより大きくして作り直してください(08)。
URL を入れると「403 レスポンス コードが返されました」
Google のチェックがそのページを開けていません。claude.ai のページではなく、GitHub Pages の URL(02)を使ってください。
Google ログインで「serverClientId must be provided」
ウェブ用クライアント ID がアプリに入っていません。Google Cloud で「ウェブ アプリケーション」のクライアントを作り、その ID を serverClientId に渡してください。
Google ログインで「DEVELOPER_ERROR」やコード 10 のエラー
Google Cloud の Android クライアントのパッケージ名か SHA-1 が、アプリと合っていません。Play から入れた版は Play の署名の SHA-1、パソコンから入れた版はアップロード鍵の SHA-1 が必要です(02)。
Google ログインで「アクセスをブロック」「このアプリはテスト中です」
そのアカウントがテストユーザーに登録されていません。Google Cloud →「対象」→「テストユーザー」に追加してください。
テストのリンクで「App not available」「招待されていません」
① テスターに登録したアドレスと、ページを開いたブラウザのアカウントが違う(スマホに複数の Google アカウントがある場合によく起こります)。② 登録直後でまだ反映されていない。数十分待つか、アカウントを切り替えて開き直してください。
Play から入れようとすると「アプリはインストールされていません」「競合」
パソコンから直接入れた版が残っています。アンインストールしてから入れ直してください(04)。
スクリーンショットがアップロードできない
縦横比は 9:16 ちょうどでないと受け付けられません。store_assets\screenshots\ の画像(1350×2400)を使ってください。
審査で却下された
メールと Play Console の「ポリシー ステータス」に理由が書かれています。多いのは、権限の申告内容とアプリの動作が合わない、プライバシーポリシーの内容が足りない、の2つです。
2026年9月の記録です。Play と Google Cloud の画面や要件は変わることがあるので、実施するときは公式のヘルプもあわせて確認してください。
